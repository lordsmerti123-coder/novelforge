# Архитектура NovelForge

Устройство проекта для того, кто продолжает работу: что своим кодом, что внешним,
как связаны процессы, откуда берутся ограничения. Измеренные величины — из
`docs/MEASUREMENTS.md`, отчёты прогонов — в `bench/measurements/`.

---

## 1. Назначение и границы

NovelForge — локальная текстовая игра с ИИ-ведущим и иллюстрациями. Ведущий ведёт
историю, генератор рисует кадры к сценам, пользователь правит мир и правила через
веб-интерфейс. Интернет в пайплайне не участвует: у процесса движка нет ни одного
внешнего соединения, всё общение идёт по петлевому интерфейсу.

**Внешнее, не принадлежит проекту:**

| Компонент | Что это | Как используется |
|---|---|---|
| FreeToken | сервер инференса, `127.0.0.1:1919` | `/v1/chat/completions`, `/v1/stats`, `/v1/cache/status` |
| ComfyUI | сервер генерации, `127.0.0.1:8188` | `/prompt`, `/history`, `/free`, `/system_stats` |
| Qwen-Image-2.1 | модель генерации (GGUF) | имена файлов в `novel/config.py`, `QWEN_T2I_GRAPH_MODELS` |
| Gemma-4, Qwen3.6, gpt-oss | текстовые модели | каталоги в реестре `novel/models.py` |

**Своё:** оркестратор (`novel/machine.py`), сборка контекста (`novel/context.py`),
хранилище (`novel/db.py`), разбор ответа модели (`novel/protocol.py`), форматы
диалога (`novel/formats.py`), инструменты сочинения (`novel/authoring.py`),
веб-интерфейс (`gui/`), измерительные прогоны (`bench/`).

Ядро ComfyUI (`COMFY_ROOT`) не изменяется: сервер запускается как
есть, командой из `novel/config.py:comfy_server_argv()`.

## 2. Три процесса

| Процесс | Порт | Кто владеет жизненным циклом |
|---|---|---|
| FreeToken | 1919 | оркестратор: останавливает и поднимает сам |
| ComfyUI | 8188 | оркестратор: поднимает напрямую, без Comfy Desktop |
| Оркестратор и интерфейс | 8760 | пользователь запускает ярлыком или `run_gui.py` |

**ComfyUI поднимает оркестратор.** Оболочка Comfy Desktop не стартует backend
сама: она ждёт нажатия Start, и до готовности сервера проходит около 3.5 минуты.
Той же командой, что и приложение, сервер поднимается напрямую за **13–17 секунд**.
Реализация — `novel/comfy.py:ensure_running(mode)`, по умолчанию `mode="direct"`;
команда собирается в `comfy_server_argv()` и включает `--extra-model-paths-config`
— без этого файла генератор не видит ни одной модели. Перед запуском проверяется
занятость порта (`_port_busy`): второй экземпляр поднимать нельзя. Comfy Desktop
для работы не нужен и может быть закрыт.

**Движок FreeToken оркестратор гасит и поднимает сам.** Остановка занимает
**0.75 с** и освобождает **9.8 GB VRAM**, 17.7 GB RAM и 32.7 GB commit. Холодный
старт — **38–53 с** до готовности и **44 с** до первого токена. Реализация —
`novel/engine.py`: `EngineController.stop()`, `cold_start()`, `wait_ready()`;
команда запуска собирается в `EngineConfig.argv()`.

## 3. Почему VRAM переключается

Обе модели на 12 227 MB не помещаются. С живым движком свободно максимум
**~2.9 GB** — это измеренный предел: `moe=128`, `swa=8777`, `kv=1024` есть
минимальная геометрия пулов, которая ещё обслуживает запросы. Генератору в пике
нужно **~11.2 GB**.

Сжатие пулов кэша проблему не решает: пересборка через `POST /v1/cache/rebuild`
отдаёт максимум **1.6 GB**. Фиксированная часть движка — резидентные веса, контекст
CUDA, буферы активаций — занимает около 6.15 GB и не освобождается вовсе. Рабочий
механизм только один: полная остановка движка.

Следствия, заложенные в код:

- кадры копятся в очередь и рисуются пачкой за одно переключение: загрузка весов
  стоит ~18 с, и выгрузка между кадрами одной пачки тратит их зря;
- политики частоты картинок по умолчанию экономят — рисовать на смене сцены, а не
  на каждом ходу;
- ход без картинки стоит 17–30 с, ход с новой иллюстрацией — 150–200 с.

## 4. Конечный автомат

`novel/machine.py`. Состояния — `State(str, Enum)`: `IDLE`, `LLM_ACTIVE`,
`SWITCH_TO_IMAGE`, `IMAGE_GEN`, `SWITCH_TO_LLM`, `SUMMARIZING`, `ERROR`.

```
IDLE ─► LLM_ACTIVE ─► SWITCH_TO_IMAGE ─► IMAGE_GEN ─► SWITCH_TO_LLM ─► IDLE
          │  ▲                                                             │
          │  └──── SUMMARIZING ◄────┐                                      │
          └─────────────────────────┴──────────────────────────────────────┘
```

| Состояние | Что происходит |
|---|---|
| `IDLE` | ничего не выполняется; сюда возвращается завершённый ход |
| `LLM_ACTIVE` | сборка контекста и запрос к движку (`_llm_turn`) |
| `SUMMARIZING` | сворачивание истории внутри хода (`_maybe_summarize`), затем возврат в `LLM_ACTIVE` |
| `SWITCH_TO_IMAGE` | остановка движка (`stop_engine`) — освобождение VRAM |
| `IMAGE_GEN` | генерация очереди кадров (`_image_phase` → `_generate_one`) и `POST /free` |
| `SWITCH_TO_LLM` | возврат движка (`ensure_engine`) |
| `ERROR` | ход прерван; в `IDLE` не возвращается, состояние видно в интерфейсе |

Точка входа — `NovelMachine.send(session_id, text, interject, images)`, вызывается
из рабочего потока интерфейса:

1. `_images_for_model` решает по политике `vision_mode`, какие изображения уйдут в
   запрос; `_store_uploads` сохраняет вложения на диск;
2. реплика игрока пишется в базу, её идентификатор исключается из окна
   (`exclude_ids`), иначе текст попал бы в промпт дважды;
3. `ContextBuilder.build` собирает запрос, `chat_stream` получает ответ,
   `parse_reply` разбирает теги;
4. `_maybe_summarize` сворачивает историю, если окно переполнено;
5. при наличии блока `<scene>` политика `_should_generate_now` решает, рисовать ли
   сейчас, и `_image_phase` при необходимости переключает VRAM.

Состояние движка проверяется через `EngineController.port_pid()` и `is_healthy()`;
`ensure_engine` поднимает движок, а `_release_comfy_if_needed` перед этим выгружает
модели генератора, если те заняли карту.

## 5. Слои контекста

`novel/context.py`, методы `ContextBuilder.stable_layers`, `window`, `build`.
Порядок слоёв не косметический: сверху неизменное, снизу то, что меняется каждый
ход.

| # | Ключ | Содержимое | Стабильность |
|---|---|---|---|
| 1 | `format` | инструкция формата и протокол ответа | стабильный |
| 2 | `world` | описание, жанр, тон, повествование | стабильный |
| 3 | `rules` | включённые правила по приоритету | стабильный |
| 4 | `characters` | характер, внешность, речь | стабильный |
| 5 | `style` | стиль иллюстраций | стабильный |
| 6 | `hidden` | скрытые правила мира, если заданы | стабильный |
| 7 | `state` | состояние партии из `world_state` | стабильный |
| 8 | `memory` | суммаризация пройденной истории | стабильный |
| 9 | `window` | последние `context_turns` сообщений дословно | меняется |
| 10 | — | текущая реплика игрока с врезкой | меняется |

Слои 1–8 помечены `stable=True` и стоят в начале запроса намеренно: движок кэширует
префикс, и на каждом ходу пересчитывается только хвост — это удерживает стоимость
prefill. Системная инструкция собирается склейкой стабильных слоёв, сообщения окна
идут после неё.

**Бюджет:** `context_budget_tokens` (16384) минус резерв под ответ `max_tokens`
(900) минус стоимость стабильных слоёв. Если стабильная часть не оставляет места,
сборка продолжается, но в `warnings` попадает предупреждение.

**Окно** набирается с конца: от свежих сообщений к старым, пока помещается; свежая
пара «реплика — ответ» ценнее старой. Исключаются сообщения, уже покрытые
суммаризацией (`id > latest_memory.through_message_id`), и явно переданные в
`exclude_ids` — текущая реплика.

**Суммаризация** сворачивает всё, что старше последних `context_turns` сообщений, и
пишет **одну** запись через `db.replace_memories`: новая сводка поглощает
предыдущие, иначе память растёт теми же темпами, что и история.

Свёрнутая часть исключается из окна: иначе старые сообщения одновременно лежали
бы в памяти и считались выброшенными, признак «пора сворачивать»
(`needs_summary`) срабатывал бы каждый ход заново, и модель получала бы одну и
ту же сводку по кругу.

**Подсчёт токенов.** Оценка по длине текста (`estimate_tokens`,
`CHARS_PER_TOKEN = 2.8`) подбирает окно до обращения к серверу; точное число даёт
`FreeTokenClient.count_tokens`. При `debug_mode` стоимость каждого слоя уточняется
отдельным запросом (`_refine_layer_tokens`), поэтому сумма послойных замеров может
на единицы расходиться с общим итогом.

## 6. Схема базы

`novel/db.py`, файл `data/novel.db`, SQLite в режиме WAL. Сохранение идёт на каждый
ход, отдельной кнопки «сохранить» нет. Текущая версия — `SCHEMA_VERSION = 3`.

```
worlds ──┬── world_rules        описание мира, правила, персонажи
         ├── characters
         └── sessions ──┬── messages ──── attachments (JSON-массив путей)
                        ├── memories      сводки, одна на партию
                        ├── scenes        кадры: промпт, seed, путь, статус
                        ├── speculative   заготовки предгенерации
                        └── world_state   ключ-значение по партии
```

Мир переиспользуется, партия — конкретное прохождение со своей историей, памятью и
кадрами. Все таблицы, принадлежащие миру или партии, имеют внешний ключ с
`ON DELETE CASCADE`: `world_rules` и `characters` на `worlds`; `messages`,
`memories`, `scenes`, `speculative` на `sessions`.

**Почему у `scenes` есть внешний ключ.** Без него удаление мира не трогает сцены,
а SQLite переиспользует освободившиеся номера партий: кадры одного мира
показываются в партии другого мира под тем же номером. Внешний ключ с каскадным
удалением закрывает это, а `check_integrity()` находит уже возникшие расхождения.

**Механизмы миграции** (все в `NovelDB.__init__`, порядок важен):

| Механизм | Когда применяется |
|---|---|
| `TABLES` | создание отсутствующих таблиц; `CREATE TABLE IF NOT EXISTS` форму существующей не меняет |
| `_migrate_table_shapes(force)` | смена формы: переименовать, создать заново, перенести колонки; `force` — из `REBUILD_WHEN_BELOW`, когда менялись ограничения, а не набор колонок |
| `_ensure_columns` | добавление колонок по `EXTRA_COLUMNS` через `ALTER TABLE ADD COLUMN`; сейчас — `messages.attachments` |
| `CARRY_EXPRESSIONS` | перенос значений, способных нарушить новое ограничение: ссылка на удалённую партию обнуляется |
| `_migrate_legacy_turns` | разовый перенос ходов из схемы без миров; таблица переименовывается в `turns_migrated_v2`, повтор исключён |
| `_purge_orphans` | удаление сцен и заготовок с висящей ссылкой, заготовок без партии и сцен, чьё сообщение принадлежит другой партии |
| `check_integrity` | шесть проверок на записи без владельца; результат виден в интерфейсе по кнопке «Проверить» |

Порядок вызовов: `executescript(SCHEMA)` → `_migrate_table_shapes` →
`_ensure_columns` → `INDEXES` → `_migrate_legacy_turns` → `_purge_orphans` → запись
версии. Индексы создаются после миграции формы: на старой таблице колонки, по
которой строится индекс, ещё нет.

## 7. Форматы диалога

`novel/formats.py`, словарь `FORMATS`, тип `DialogueFormat`. Формат задаёт не
только стиль текста, но и **протокол ответа** — какие служебные блоки модель
обязана вернуть, — и вид ленты в интерфейсе.

| Ключ | `wants_scene` | `scene_role` | `ui` | Картинок по умолчанию |
|---|---|---|---|---|
| `story` | да | `illustration` | `prose` | при смене сцены |
| `story_terse` | да | `illustration` | `prose` | при смене сцены |
| `chat` | **нет** | `none` | `chat` | по кнопке |
| `chat_photo` | да | **`photo`** | `photo_chat` | каждый ход |
| `chat_scene` | да | `illustration` | `chat` | при смене сцены |

`wants_scene` управляет тем, попадёт ли в инструкцию блок `<scene>` с примером JSON
(`prompts.protocol_block`); `scene_role` — как блок трактуется: у `chat_photo` это
вложение к сообщению, у остальных иллюстрация сцены. `wants_speculative` включает
блок заготовок, `ui` выбирает отрисовку в `renderMessages`.

Разбор ответа терпимый (`novel/protocol.py`): модель может не закрыть тег, обернуть
JSON в markdown-ограждение, поставить висячую запятую. Текст для игрока
(`<prose>`) возвращается даже тогда, когда машинные блоки разобрать не удалось.
Блоки `<scene>` и `<speculative>` обратно в контекст не возвращаются.

Политика частоты генерации — настройка `image_policy` со значениями `never`,
`on_scene_change`, `every_turn`, `every_n`, `manual`, `idle` (подписи — в
`IMAGE_POLICIES`). Решение принимает `NovelMachine._should_generate_now`: сцена
создаётся всегда, когда модель её прислала, политика решает только, рисовать ли
сейчас.

## 8. Ключевые модули

| Модуль | Зона ответственности | Что важно знать |
|---|---|---|
| `novel/config.py` | пути, порты, имена моделей, команда запуска ComfyUI | всё переопределяется переменными `NOVELFORGE_*` |
| `novel/metrics.py` | замеры VRAM, RAM, commit; фоновый `Sampler` | VRAM — через `nvidia-smi`; commit — через `GlobalMemoryStatusEx`, `PERFORMANCE_INFORMATION` на этой сборке Windows возвращает меньше байт, чем объявлено |
| `novel/procutil.py` | скрытые запуски и аварийная остановка | любой `subprocess` — через `hidden_kwargs`, иначе у пользователя мельтешат консоли |
| `novel/freetoken.py` | клиент движка: чат, поток, токены, размышления | `ft` в PowerShell — алиас `Format-Table`, CLI зовётся `freetoken`; `--memory-ratio` считается от **полной** VRAM, порог ~0.62; `kv=1` не обслуживает запросы; аргументы отключения размышлений движок отдаёт в `geometry.reasoning.kwargs`; `vram_bytes` равен нулю до первого запроса |
| `novel/engine.py` | запуск, остановка и наблюдение движка | остановка 0.75 с и −9.8 GB; холодный старт 38–53 с; RSS считается по всему дереву процессов, а не по `ft.exe` |
| `novel/comfy.py` | клиент ComfyUI, сборка графа, прямой запуск сервера | идентификаторы узлов в ссылках — строки (`["4", 0]`); референс передаётся плоским ключом `images.image_1`; `ensure_running("direct")` — 13–17 с против 3.5 минут у Desktop; UI-воркфлоу в API не отправится |
| `novel/protocol.py` | разбор тегов, терпимый `loads_json` | потеря текста для игрока — единственный недопустимый исход разбора |
| `novel/prompts.py` | блоки промпта и шаблоны служебных вызовов | подстановка только через `render`: `str.format` ломается о примеры JSON с фигурными скобками |
| `novel/formats.py` | форматы диалога и политики картинок | формат меняет протокол ответа, а не только стиль |
| `novel/presets.py` | заготовки миров | внешность персонажей обязательна: без неё генератор рисует разных людей в разных кадрах |
| `novel/models.py` | реестр моделей и пресеты сэмплинга | ищет каталоги safetensors, родной формат FTW и GGUF; пресеты — значения по умолчанию, пользователь их переопределяет |
| `novel/settings.py` | настройки пользователя | dataclass и `data/settings.json`; неизвестные ключи при чтении игнорируются, незнакомые при правке отклоняются |
| `novel/db.py` | хранилище и миграции | SQLite переиспользует номера после удаления, поэтому внешние ключи для всего, что принадлежит партии, обязательны |
| `novel/context.py` | слои, бюджет, окно, суммаризация | порядок слоёв удерживает кэш префикса; свёрнутое исключается из окна |
| `novel/authoring.py` | сочинение миров, правил, персонажей, завязок | вне игрового хода: у писателя другой формат ответа, размышления выключаются |
| `novel/vision.py` | подготовка изображений к отправке | base64 data URL работает без флагов; кадр 768×768 — около 258 токенов входа |
| `novel/machine.py` | конечный автомат и владение VRAM | единственное место, где принимаются решения о переключении движков |
| `gui/app.py` | HTTP-интерфейс | синглтоны `_db`, `_settings_store`, `_registry`, `_machine`; тяжёлое — через `_run_task`; имя файла для `Content-Disposition` проходит `_safe_filename`, потому что заголовки latin-1 и кириллицу рвут |
| `gui/static/index.html` | вся страница: разметка, стили, скрипт | имена полей настроек перечислены в `NUM_FIELDS`/`BOOL_FIELDS`/`STR_FIELDS` |
| `launcher.py` | запуск с ярлыка | `pythonw` при падении молчит, поэтому запускатель пишет `logs/gui_start.log` и показывает окно с ошибкой |
